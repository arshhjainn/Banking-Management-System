# RDBMS syllabus map

`schema.sql` and `ER_DIAGRAM.md` cover entities, attributes, keys, domains, constraints and ER conversion. `database/demos/queries.sql` covers DDL/DML/DCL, selection/projection, joins, union, set difference, subqueries, aggregates/HAVING, views, EXPLAIN, indexes and a transaction with row lock/savepoint/rollback. `views.sql`, `triggers.sql`, and `procedures.sql` demonstrate advanced SQL. The procedure is educational reporting; Flask alone performs money operations. A MySQL cursor is represented in the application through connector cursor objects; SQL cursors are appropriate for row-by-row stored-program teaching, but no cursor procedure is needed for this simple reporting case.

ACID: atomic updates/inserts, consistent constraints, isolated row locks, durable commit. Consistent lock ordering reduces deadlocks; MySQL may still detect one, in which case the client should retry the whole transaction. Serializability means concurrent schedules match some serial order. InnoDB uses undo/redo logs and checkpoints for recovery. Timestamp ordering is a concurrency-control theory; this app uses InnoDB locking instead. File systems lack relational constraints and declarative queries. Hashing supports equality lookup; B/B+ trees support ordered/range access and are commonly used for indexes. Multilevel indexes reduce lookup depth. RAID combines disks for performance/redundancy. Distributed databases span nodes; parallel databases execute work concurrently. These storage/system topics are conceptual only; no custom storage engine is built.
